Mobile UX Redesign

Cornell Enrollment Mobile App

Cornell’s Student Center was designed primarily for desktop workflows, yet students frequently manage enrollment on their phones between classes. This project explores how a mobile-first redesign can make enrollment faster, clearer, and less stressful.

Overview

The Cornell Enrollment Mobile App reimagines the Student Center experience as a guided mobile workflow instead of a dense, table-based system.

Rather than asking students to interpret complex information across multiple pages, the redesigned experience prioritizes clarity, speed, and confidence during decision-making.

1. Empathize

To understand how students interact with the enrollment system, I conducted informal interviews and walkthrough sessions with Cornell undergraduates during add/drop week.

Students were asked to walk through how they normally add a class, drop a class, and swap a class, and were observed navigating the current Student Center interface.

Participants

  • 6 Cornell undergraduate students
  • First-year to senior
  • Mix of majors across engineering, arts, and sciences

Key Observations

  • Students hesitate before confirming enrollment changes
  • Swap is perceived as risky and unclear
  • Important information is buried in dense tables
  • Students double-check schedules after submitting actions
  • Mobile experience is difficult and not optimized

Key Insight: The core problem is not just usability. It is lack of confidence during high-stakes actions.

2. Define

Students need a faster and safer way to manage enrollment on mobile devices without feeling uncertain about the outcome of their actions.

The current system slows decision-making because it requires navigating multiple pages, presents information in dense tables, and provides weak feedback after actions.

Design Goals

  • Reduce cognitive load
  • Increase confidence in risky actions
  • Improve mobile navigation
  • Improve system feedback

3. Ideate

After synthesizing research insights, I explored ways to restructure the enrollment experience for mobile.

The ideation process focused on reducing cognitive load, increasing confidence in risky actions, improving navigation speed, and handling edge cases such as conflicts, waitlists, and prerequisites.

Concept Direction

A key idea was shifting enrollment from a form-based system into a guided workflow. Instead of navigating tables and forms, users move through Select → Review → Confirm → Result.

Design Directions Explored

  • Card-based course layout for faster scanning
  • Step-by-step enrollment flows
  • Side-by-side swap preview
  • Visual schedule blocks for conflict detection
  • Clear status indicators
  • Strong confirmation and success states

4. Prototype

Mid-fidelity wireframes were created to test structure and flows before visual design.

Focus Areas

  • Clear action hierarchy
  • Guided step-by-step flows
  • Improved scanability
  • Visibility of important information

Key Flows

  • Student Center dashboard
  • Add course flow
  • Swap course flow
  • Drop course flow
  • Schedule view

Final Design Features

  • Card-based UI for easy scanning
  • Clear status indicators
  • Guided enrollment flows
  • Visual schedule blocks
  • Strong confirmation feedback

5. Test

Quick usability testing was conducted with students using the prototype.

Tasks

  • Add a class
  • Swap a class
  • Drop a class

Results

  • Students completed tasks faster
  • Less hesitation before confirming actions
  • Swap preview increased confidence
  • Schedule blocks improved understanding of conflicts
  • Confirmation screens reduced need to double-check

Key Insight: Strong feedback and structured flows significantly reduce uncertainty.

Reflection

This project highlighted how administrative systems often prioritize functionality over user confidence.

While the original system technically works, it creates unnecessary stress during an already high-pressure process.

What I Learned

  • UX is not just about efficiency. It is about confidence
  • Clear feedback is critical in high-risk interactions
  • Mobile-first design requires rethinking structure, not just resizing screens

Future Improvements

  • Real-time waitlist updates
  • Push notifications for seat availability
  • Integration with long-term academic planning tools
